# 战斗日志系统说明

## 日志复现能力

当前的日志系统已经包含了足够的信息，可以根据**场景快照**和**程序底层代码**完全复现游戏流程。每条日志条目都包含：

### 1. 伤害计算日志（完整伤害管线）

每条伤害日志包含：
- **基础攻击力** (`baseAttack`)
- **有效攻击力** (`effectiveAttack`) - 包含所有倍率后的最终攻击力
- **基础伤害** (`baseDamage`) - 攻防差计算后的伤害
- **最终伤害** (`finalDamage`)
- **复现上下文**：
  - `attackerMorale`: 攻击者士气值
  - `attackerTerrainMod`: 攻击者地形攻击倍率
  - `attackerBuffs`: 攻击者Buff列表（类型和数值）
  - `skillMultiplier`: 技能倍率
  - `splashFactor`: 溅射系数
  - `critMultiplier`: 暴击倍率
  - `damageTakenMultiplier`: 目标受伤倍率（地形减伤等）
  - `targetDefense`: 目标防御值
  - `targetTerrainMod`: 目标地形减伤倍率

**复现方法**：使用这些参数，按照伤害管线公式重新计算，应该得到完全相同的 `finalDamage`。

### 2. 攻击日志（完整索敌过程）

每条攻击日志包含：
- **攻击者和目标信息**：单位ID、模板ID、位置、所有者
- **索敌信息** (`targetSelection`)：
  - `availableTargets`: 可攻击目标数量
  - `priorityRules`: 目标优先级规则
  - `selectedTargetDistance`: 选中目标的距离
  - `allCandidates`: 所有候选目标的完整列表（ID、模板、距离、位置）

**复现方法**：使用相同的索敌逻辑和优先级规则，应该选择相同的目标。

### 3. 移动日志（完整移动上下文）

每条移动日志包含：
- **移动信息**：起始位置、目标位置、移动距离
- **移动上下文** (`moveContext`)：
  - `baseMoveSpeed`: 基础移动速度
  - `terrainMoveBonus`: 地形移动加成
  - `terrainMoveCost`: 目标地形移动消耗
  - `morale`: 当前士气值
  - `isOrkEnemy`: 是否为兽人敌人（影响士气效果）
  - `maxCol`: 最大前进列
  - `direction`: 移动方向

**复现方法**：使用这些参数，按照移动逻辑重新计算，应该得到相同的移动结果。

### 4. 部署日志

包含：
- 单位ID、模板ID、位置
- 部署成本、部署延迟
- 初始HP、最大HP
- 是否为基地部署

### 5. 死亡日志

包含：
- 被击杀单位信息
- 击杀者信息
- 最终HP

## 日志自动保存

### 保存机制

- **每回合结束时**，自动保存本回合的增量日志
- 保存格式：JSON（包含完整数据）
- 文件名格式：`turn-{回合号}-incremental-{时间戳}.json`

### 浏览器环境限制

由于浏览器安全限制，无法直接在项目文件夹中创建文件。日志文件会通过**浏览器下载**的方式保存到用户的下载文件夹。

### 日志文件内容

每个增量日志文件包含：
```json
{
  "turnNumber": 回合号,
  "timestamp": 时间戳,
  "entryCount": 条目数量,
  "entries": [日志条目数组]
}
```

### 手动导出完整日志

在调试控制台的"日志"标签页中，可以：
- 导出为文本格式（人类可读）
- 导出为JSON格式（完整数据）

## 使用日志进行问题诊断

1. **定位问题回合**：查看日志文件，找到问题发生的回合
2. **查看详细日志**：检查该回合的所有日志条目
3. **复现计算**：使用日志中的参数，按照代码逻辑重新计算
4. **对比结果**：如果计算结果与日志不一致，说明代码逻辑有问题

## 注意事项

- 日志文件会累积，建议定期清理
- 随机事件（如暴击）的结果已记录在日志中，复现时使用相同的结果
- 日志中的时间戳是生成时间，不是游戏内时间

## 快照作为测试用例（Snapshot-as-Testcase）

你可以把“战场形势”做成快照文件并在调试面板中恢复，用来验证引擎逻辑。
但**手动编辑快照**时必须遵守一些硬规则，否则会导致加载后出现隐蔽错误。

### 必须满足的规则（部分）
- **battleCards.id 唯一**：不能存在“同名卡牌/重复 ID”。
- **牌组引用一致**：`hand/deck/discardPile` 中引用的 `battleCardId` 必须存在于 `config.battleCards`。
- **unitTemplates.id 唯一**：模板 ID 不能重复。
- **单位引用有效模板**：`unit.templateId` 必须存在于 `config.unitTemplates`。
- **单位坐标合法**：`(row,col)` 不能越界。
- **占格不冲突**：同一格、同一 `space layer` 不能被两个单位同时占用（空地分层允许同格不同层共存）。

### 自动校验
引擎在 `restoreBattleSnapshot` 时会执行 `validateBattleSnapshot`，若违反上述规则会直接报错并给出具体原因，方便你修正快照。
