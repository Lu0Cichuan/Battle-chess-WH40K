### 10. 战役 / 星系 结构与战术Roguelite循环

#### 设计状态
- ✅ 已初步确定宏观结构：**星系 → 章节 → 战役**。
- ✅ 已在 `campaignConfig.ts` 中实现最小可用结构：`初始星系-教程章节-战役 0.1 Test`，作为战斗入口。
- ❌ 未实现星系内资源重置 / 遗落战利品 / 科技与指挥官成长等系统。

#### 目标结构（设计草案）
- **星系（Galaxy）**
  - 决定本星系中可能遭遇的种族、事件与战役节点。
  - 进入新星系时：
    - 重置：仓库、背包、可用军队列表（相当于重新开一局）。
    - 保留：科技加点、指挥官等级、永久解锁的亲卫位/保险库位等“账号级/指挥官级”进度。
- **章节（GalaxyChapter）**
  - 星系内的一个连续行动段落（类似战役章节）。
  - 每个章节开始时：
    - 获得一次性补给（资源、基础兵员/卡牌）。
    - 整理仓库与背包、编制军队编制；之后进入该章节下的战役链路。
  - 同一章节内的多场战役之间：
    - **不能**从星系“全局仓库”再取物资，只能使用章节开始时发放/整理好的内容和战役中获取的临时补给。
- **战役（GalaxyBattle）**
  - 单场战斗（对应一个 `BattleConfig`），消耗和掉落都只在章节局部范围内生效。
  - 失败处理逻辑（Roguelite 要素）：
    - 除了科技加点带来的“亲卫”与“保险库插槽”内的物品，其余背包物品与军队全部判定为**遗落在失败战役的地图上**。
    - 再次行军经过该战役节点时：
      - 触发“打捞/找回事件”：根据配置只返还部分遗落军队/物资（可能带惩罚或事件分支）。

#### 需要实现
- [ ] `Galaxy / GalaxyChapter / GalaxyBattle` 与战役进度保存结构的最终版（持久化到战役存档）。
- [ ] 星系级重置逻辑：进入新星系时，重置仓库/背包/军队，只保留科技与指挥官进度。
- [ ] 章节级开局流程：补给发放、背包整理、可用军队构建、进入第一场战役。
- [ ] 章节内战役失败逻辑：
  - [ ] 识别科技/保险库保护的单位与物品，防止被清空。
  - [ ] 将其余背包与在场军队标记为“遗落在某战役节点”。
  - [ ] 为每个遗落节点记录可回收的军队/物资信息。
- [ ] 再次抵达遗落节点时的“打捞”事件流程：
  - [ ] 计算可回收比例/条目（可能受科技/难度影响）。
  - [ ] 允许玩家在有限的回收名额中做选择（优先回收精锐、卡组核心等）。
- [ ] 指挥官层面的科技加点与亲卫/保险库位系统接口（为后续 UI 实现预留字段）。

## 开发优先级建议

### 第一阶段（核心功能完善）
1. 更复杂的攻击规则（基于 attackPatternConfig 和锁定目标系统继续扩展）
2. UI/UX 改进
3. 地形高级效果（目前已实现基础 directional.funnelDirection，引流逻辑仍为 MVP）
   - [ ] 掩体机制标准化：将 `TerrainEffects.damageTakenModifier` 统一为 40K 风格的掩体规则（轻掩体：远程减伤 ~20%；重掩体：远程减伤 ~50%；近战无视掩体）。
   - [ ] 远程/近战区分：在攻击/伤害管线中区分“远程攻击”与“近战攻击”，确保掩体只对远程生效，近战进入掩体格后照常结算。
   - [ ] 特殊“草丛”地形：为某些地形添加“远程不可索敌，仅近战可攻击”的规则（远程无法将草丛内单位列入候选目标集，但近战在相邻或同格时仍可攻击）。
   - [ ] 日志与可视化：在日志中记录掩体/草丛对索敌与伤害的影响，并在 UI 上以图标/提示说明当前单位享受的掩体类型与减伤比例。

### 第二阶段（功能增强）
1. 卡牌组织标识系统
2. 特殊移动模式
3. 战斗事件系统

### 第三阶段（高级功能）
1. 战斗结算增强
2. 战斗回放系统
3. 多人对战支持
